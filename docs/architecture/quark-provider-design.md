# 夸克网盘 Provider 接入设计草案

- 状态：Cookie 私有接口已完成真实转存验收；OpenList OpenAPI 保留为可选能力
- 日期：2026-08-25
- 目标版本：v0.2.0 之后
- 运行时影响：夸克实验性订阅和转存启用；不进入 v0.2.0 正式版基线

阶段进度：私有 Cookie Provider 已完成只读和跨账号单项转存真实验收，并以
`experimental` 状态开放订阅；OpenList Open Provider、双凭证加密保存和前端绑定已
完成离线实现，但 OpenAPI 不是分享转存的前置条件。OpenAPI 核查结论见
[夸克 OpenAPI 托管授权 Q0 门禁](quark-open-api-q0.md)。

本文只确定夸克网盘接入的边界、验证门禁和实施顺序，不改变 rc.17，也不承诺当前
已经具备可用的夸克接口。

## 1. 前置结论

MediaSync 已有通用 `CloudDriveProvider` 协议，扫描和转存 Service 依赖通用 DTO，
四张核心业务表也已经用 `provider` 隔离云盘类型。因此夸克接入应作为新的 Provider
实现合入现有骨架，不新增一套订阅、文件或任务模型。

截至 2026-08-24，在夸克官方域名范围内能确认
[夸克网盘 Web 产品](https://pan.quark.cn/)和
[夸克网盘会员服务协议](https://b.quark.cn/apps/quark_icloud_pay/routes/service_help)，
但没有找到可供第三方服务端集成的公开官方网盘 API 文档。这里的“没有找到”是
本次检索结论，不是夸克官方关于 API 是否存在的声明。

因此当前不能把接入描述成“官方 API 集成”，也不能在设计中猜测私有端点、Cookie
字段或请求签名。进入实现前必须先满足以下二选一条件：

1. 获得可验证的官方或正式授权 API 文档、凭证申请方式和使用条款；或
2. 维护者明确批准实验性 Web 私有接口路线，接受接口失效、账号风控和条款变化
   风险，并确认拟采用方式符合适用条款。

维护者于 2026-08-25 批准实验性 Cookie 私有接口；后续真实转存验证确认 Cookie
已经覆盖分享链路、账号盘浏览、查重、建目录和写入。匹配的 OpenList Refresh Token、
AppID 和 SignKey 只保留为可选账号盘 OpenAPI，不是订阅或转存前置条件。

Q0 静态能力验证结果见
[夸克私有接口 Q0 验证记录](quark-private-api-q0.md)。

## 2. 设计边界

### 2.1 沿用现有业务骨架

- `cloud_accounts` 保存账号归属、Provider、状态和加密凭证。
- `subscriptions` 保存分享来源、目标路径、周期和账号关联。
- `files` 继续承担增量检测、源文件身份和转存结果索引。
- `tasks` 继续承担扫描、转存、重试、租约和执行追踪。
- API、Scheduler、Worker 和 Service 不得直接读取夸克响应字段。
- 夸克特有字段只能进入 Provider 内部模型或通用 `RemoteItem.metadata`。

首个实现不增加新的核心业务表。认证方式未确认前也不修改数据库凭证字段；先通过
能力门禁确定凭证是 OAuth token、可轮换 token 还是其他授权材料，再提出最小的
加法迁移。不得为了赶进度把明文 Cookie、二维码会话或设备标识塞入
`refresh_token` 字段。

### 2.2 不属于首个版本的内容

- 跨账号搬运、秒传优化、分享创建和外链下载；
- 通用文件管理器、播放、STRM、刮削或媒体库管理；
- 自动绕过验证码、风控、设备校验或服务限制；
- 未经明确批准的抓包、逆向接口和浏览器会话劫持；
- 为夸克复制一套专用任务表或绕过现有幂等状态机。

## 3. Provider 契约映射

夸克实现必须完整映射现有 `backend/app/providers/base.py`，不能让未实现能力在运行
时才随机失败。

| 通用能力 | 夸克验收语义 |
|---|---|
| `validate_account` | 验证凭证并返回稳定用户标识、默认 Drive 和可选 Drive 列表 |
| `resolve_share` | 解析分享 URL、密码和稳定分享键，不在日志中回显密码 |
| `list_share_items` | 分页列出分享目录，稳定映射文件 ID、父 ID、类型、大小和时间 |
| `resolve_target_path` | 把用户路径解析为稳定目标目录 ID |
| `list_target_items` | 分页列出目标目录，用于查重和结果对账 |
| `ensure_folder` | 已存在时返回同一目录，不因重试创建重复目录 |
| `find_target_item` | 在写操作前后按稳定标识优先、名称兜底进行核对 |
| `save_shared_item` | 将一个分享项保存到目标目录，并返回可核验的目标 ID 和路径 |
| `consume_refresh_token_update` | 只返回经过验证的新凭证；没有轮换机制时始终返回 `None` |

Q2 实测只能确认会话有效，未取得适合跨会话持久化的稳定用户 ID。因此只读适配返回
通用账号身份和根目录 `0`。允许白名单内的 `__puus`/`__pus` 轮换，并通过现有加密
凭证字段原子更新；私有接口未返回 user_id 时，两套凭证只能分别验证，不能自动执行
同账号 ID 比对。

如果实际接口无法可靠返回目标 ID，或者写入超时后无法查询最终结果，
`share_save` 能力不得启用。仅实现账号验证或目录浏览时，应通过 Provider 元数据
准确暴露部分能力，前端不得展示不可用操作。

## 4. 实现隔离

Q2 已按下面的边界落地：

```text
backend/app/providers/quark/
├── provider.py          # 已注册的私有只读协议适配和 DTO 映射
├── open_provider.py     # OpenList 刷新、OpenAPI 签名、账号盘和目录能力
├── readonly_probe.py    # 固定端点、超时、有限重试、响应校验和错误分类
└── cli.py               # 无持久化的本机实时诊断入口
```

如果后续重新评审并采用实验性 Web 私有接口，则目录改为
`backend/app/providers/quark/private_provider.py` 等显式命名，并满足：

- 默认关闭，只能通过明确配置启用；
- 使用维护者自有测试账号验证，不提交任何真实凭证或网络响应；
- 所有端点、请求头和响应结构都封装在 Provider 内；
- 登录失效应转换为确定的凭证过期错误，不能循环重试或静默停摆；
- 日志、异常、Task payload 和 API 响应统一脱敏；
- 能力元数据标记为 `experimental`，界面显示上游不稳定风险。

## 5. 可靠性和安全要求

### 5.1 读取与限流

- 网络错误、`429` 和可恢复的 `5xx` 可做有上限的指数退避，并加入抖动。
- `401`、`403`、验证码、风控和权限错误立即停止，更新账号状态并提示重新授权。
- 分页游标只由 Provider 解释，Service 只消费 `RemotePage.next_marker`。
- 设置连接、读取和整次操作超时；禁止无限轮询。

### 5.2 写入与幂等

- 保存请求不得因超时直接做 HTTP 级重放。
- 写前先核对目标，写后必须通过目标目录查询确认结果。
- 结果不明确时返回“待对账”，由现有任务执行模型接管，不能标记成功或创建第二个
  转存任务。
- 只有在目标存在性可以可靠核验后，才允许有限业务重试。
- 文件和任务的数据库幂等约束继续是最终防线，Provider 不得绕过。

如果现有 `save_shared_item` 返回模型不足以表达“请求结果未知、需要对账”，应先为
所有 Provider 提出通用契约升级，不得只在夸克实现中藏特殊状态。

### 5.3 凭证

- 凭证必须使用现有加密机制或经批准的通用加密凭证字段保存。
- API 永不返回凭证，前端也不持久化凭证副本。
- 凭证轮换只有在新凭证通过账号校验后才能落库。
- 不记录完整 Cookie、token、分享密码、二维码内容或设备标识。
- 认证材料的字段设计必须在真实授权机制确认后单独评审。

## 6. API 与前端

业务操作继续沿用账号、订阅、文件、任务和系统信息 API。账号认证增加最小的
`/quark/qr-login/start` 与 `/quark/qr-login/{session_id}` 路由：二维码会话、token、
service ticket 和 Cookie 只保存在 API 进程内，确认后复用通用账号加密与校验服务，
不建立夸克专用持久化模型。

`/system/info` 的 Provider 元数据应成为前端能力来源：

- Provider 选择器只展示注册表返回的类型和状态；
- 账号表单按 Provider 和认证模式展示字段；
- 夸克 OpenAPI 配置只允许 OpenList 模式，并明确整项为可选；只有启用时才要求匹配的
  Refresh Token、AppID 和 SignKey；
- 订阅所选账号决定 Provider，服务端拒绝账号与订阅 Provider 不一致；
- 夸克账号允许提交和校验；缺少 `share_save` 时不能提交订阅；
- `share_save` 不可用时，界面只能做已声明的只读操作。

## 7. 测试与验收

每个实现阶段至少覆盖：

1. Provider 契约测试：账号、分享、分页、空目录、嵌套目录和异常响应。
2. 凭证测试：过期、轮换、错误账号、脱敏以及日志中无秘密材料。
3. 限流测试：`429`、网络超时和 `5xx` 的有界读取重试。
4. 写入测试：超时不重放、写前查重、写后对账和重复任务不重复保存。
5. Service 集成测试：扫描、文件增量、任务状态和 Provider 错误映射。
6. 前端测试：Provider 切换、能力禁用、账号与订阅 Provider 一致性。
7. 数据迁移测试：如需迁移，必须覆盖旧库升级和全新数据库建库。
8. 外部验收：使用维护者自有测试账号验证真实接口；这一结果必须单独记录，Mock
   或离线测试不能证明真实云盘可用。

测试夹具只保存人工构造或完全脱敏的数据。不得把抓取的真实响应、Cookie 或用户
文件元数据提交到仓库。

## 8. 分阶段实施

1. **Q0 能力门禁**：确认授权方式、条款、可用 API、稳定标识、分页、限流和写后
   对账能力，更新本设计并取得维护者批准。
2. **Q1 通用展示（已完成）**：前端按 Provider 元数据渲染账号和订阅能力。
3. **Q2 私有只读适配（已完成）**：已实现账号、根目录和测试分享
   诊断入口，于 2026-08-25 完成本机实时验证，并完成正式只读 Provider、分页 DTO
   映射和显式禁写能力。
4. **Q3 OpenAPI 双凭证（离线实现完成）**：复用现有加密字段，完成 OpenList 刷新、
   签名、账号、分页、目录和前端绑定；等待维护者真实凭证验收。
5. **Q4 私有写能力（已完成）**：已实现目录创建、分享转存提交和 operation 查询，
   并完成跨账号单项分享真实写入验收；不由 OpenAPI 冒充分享能力。
6. **Q5 转存与恢复（已完成）**：已实现写入 intent、operation ID 持久化、恢复查询
   和不确定结果终止自动重放，见 ADR-0003。
7. **Q6 订阅启用（已完成）**：真实写入、目标复核和 Cookie 内存轮换已通过，现声明
   `share_save`，状态保持 `experimental`。

每阶段独立提交、可测试、可回退。Q3 的 Mock 和离线测试不能代替真实 OpenList token
验收，Q5 未通过时绝不对用户暴露自动转存。

## 9. 实施前需要维护者批准的决定

- 真实认证材料的类型、生命周期和安全存储模型；
- 接口是否能满足写后对账，以及无法满足时是否只提供只读能力；
- 测试账号、限流预算和可接受的账号风控风险；
- 私有接口无法返回稳定 user_id 时，是否接受维护者人工确认两套凭证属于同一账号。

OpenList OpenAPI 后续可单独继续验收，用于账号盘浏览等官方能力，但不阻塞 Cookie
私有接口的分享订阅。已知限制是目标账号不能把自己创建的分享转存回同一账号；
`404/41017` 必须作为确定拒绝停止重试。
