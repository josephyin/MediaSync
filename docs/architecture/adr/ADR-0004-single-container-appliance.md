# ADR-0004：默认单容器 Appliance，保留多进程职责边界

- 状态：提议中
- 日期：2026-07-28
- 决策者：MediaSync 维护者
- 取代：ADR-0003
- 被取代：无
- 相关内容：[v0.2.0-rc.3 单容器 Appliance 模式设计](../single-container-appliance-rc3.md)

## 背景

ADR-0003 决定每个版本只发布一个 OCI 镜像，同时让官方 Compose 使用多个容器
分别运行迁移、对账、API、Scheduler、Worker 和前端。该决策保持了清晰的容器
生命周期，但普通 NAS 用户仍需理解和维护六个服务。

飞牛、群晖和其他图形化 Docker 平台的普通安装预期是：下载一个镜像、映射一个
端口和一个数据目录后直接启动。rc.2 的“单镜像、多容器”降低了发布成本，却
没有达到这一用户体验。

Task Engine v2 已具备持久化队列、租约、fencing、重试和恢复能力。只要 API、
Scheduler 和 Worker 继续作为独立进程运行，并保持职责边界，把它们放入同一个
容器不会把任务执行重新耦合进 API 生命周期。

## 决策

MediaSync 从 v0.2.0-rc.3 开始，把单容器 Appliance 模式作为普通用户默认且受
支持的部署方式。

默认容器入口运行一个内置 Launcher。Launcher 先完成持久化配置准备、数据库
迁移和旧任务对账，再启动相互独立的 Nginx、API、Scheduler 和 Worker 子进程。
Launcher 只管理生命周期，不执行任何业务任务。

高级多容器 Compose 继续受支持。显式服务命令仍可让每个容器只运行一个主进程。

单一镜像继续是发布边界；进程职责继续是业务架构边界；容器不再是唯一受支持的
进程隔离边界。

## 不变量

- 每个版本仍然只发布一个 `mediasync` OCI 镜像。
- API、Scheduler 和 Worker 必须是独立操作系统进程。
- API 不执行扫描和转存。
- Scheduler 只发现到期订阅并创建任务。
- Worker 是唯一任务执行者。
- Launcher 不执行调度、扫描、转存或 Provider 调用。
- SQLite 部署只运行一个 Scheduler 和一个 Worker，Worker 并发度为 1。
- 数据库迁移和旧任务对账必须在 Worker 启动前成功完成。
- 任一关键子进程异常退出时，Appliance 容器必须快速失败，不能保持半失效运行。
- 数据库和凭证密钥必须一起持久化在 `/data` 的备份边界内。
- 多容器模式与 Appliance 模式不得同时访问同一个 SQLite 数据库。
- 精确镜像标签发布后不可覆盖。

## 后果

收益：

- 普通用户可以直接在 Docker Hub 或 NAS 图形界面安装；
- 默认部署只需要一个端口和一个数据目录；
- 数据库、密钥和备份边界统一为 `/data`；
- 不再要求普通用户维护 Compose 服务依赖；
- 同一镜像仍能支持高级多容器部署和职责级调试。

成本：

- 一个子进程崩溃会重启整个容器；
- 需要维护可靠的 PID 1、信号转发、子进程回收和健康聚合；
- 单容器日志包含多个进程来源；
- 单容器不能提供容器级职责隔离；
- 首次启动和密钥持久化成为正式运行时契约；
- 维护者必须同时验证默认 Appliance 和高级 Compose 两种部署模式。

## 已考虑的备选方案

### 继续只支持多容器 Compose

容器职责最清晰，运行时监管交给 Docker Compose，但普通 NAS 用户的安装成本
过高，单镜像没有转化为预期的单容器体验，因此不再作为唯一默认方案。

### 把 Scheduler 和 Worker 放回 FastAPI 生命周期

容器内只需一个 Python 主进程，但 API 重启会直接控制任务执行，也会破坏已建立
的职责边界和独立故障模型，因此拒绝。

### 使用 systemd 或 Docker-in-Docker

可以提供成熟的进程监管，却会增加权限、镜像体积和 NAS 环境差异。Docker Socket
还会显著扩大攻击面，因此拒绝。

### 仅提供一键安装脚本生成 Compose

脚本可以隐藏部分复杂度，但飞牛等图形化平台用户仍然无法通过“下载镜像并运行”
完成安装，也增加了脚本来源和更新风险，因此不作为默认方案。

### 取消高级多容器模式

可以减少测试矩阵，但会失去职责级故障隔离和架构验证能力，也会让未来更高级的
部署方案缺少稳定入口，因此拒绝。

## 未来复审

出现以下情况时，应通过新 ADR 复审本决定：

- Launcher 长期成为高频故障来源；
- 单容器故障耦合显著影响任务可靠性；
- 两种部署模式的维护成本超过用户体验收益；
- 项目引入 PostgreSQL、多 Worker 或外部队列；
- NAS 平台普遍提供同等简单的一键 Compose 安装能力；
- 安全审计要求每个职责使用独立容器或最小权限运行时。
