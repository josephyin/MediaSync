# ADR-0005：Docker Socket 可选一键镜像升级

- 状态：已接受
- 日期：2026-07-31
- 决策者：MediaSync 维护者
- 取代：无
- 被取代：无
- 相关内容：[Docker Socket 一键镜像升级设计](../docker-socket-one-click-update.md)

## 背景

默认单容器 Appliance 让普通 NAS 用户可以通过一个镜像、一个端口和一个数据
目录运行 MediaSync，但镜像升级仍要求用户在容器管理器中下载镜像并重建容器。

Watchtower 可以自动完成这项工作，却要求用户长期运行另一个拥有 Docker 管理
权限的应用。容器内部覆盖程序文件虽然操作简单，但会让运行代码与 OCI 镜像版本
不一致，也难以可靠验证和回滚。

Docker Socket 可以让 MediaSync 通过 Docker Engine API 重建自身，但它同时
提供接近宿主机 Docker 管理员的权限。ADR-0004 因此拒绝把 Docker Socket 或
Docker-in-Docker 作为默认 Appliance 依赖。

用户明确启用的可选更新能力与“默认依赖 Docker Socket”不是同一个决策，需要
在不削弱默认安全边界的前提下单独约束。

## 决策

MediaSync 允许默认单容器 Appliance 通过可选 Docker Socket 挂载提供 Web 一键
镜像升级。

默认部署不挂载 Socket，现有同步能力不依赖 Docker Engine API。只有管理员显式
挂载 Socket、能力探测成功并再次确认风险后，一键安装入口才可用。

完整镜像切换由按需创建的临时 updater 助手容器完成。助手不是常驻应用，完成
升级或回滚后自动删除。运行版本继续由官方不可变 OCI 镜像和精确 digest 定义，
不允许在容器内覆盖程序文件模拟镜像升级。

本决策补充 ADR-0004，不取代 ADR-0004。默认单容器 Appliance、内部进程职责
边界和“不把 Docker Socket 作为默认依赖”的决定保持有效。

## 不变量

- Docker Socket 永远是显式选择的高权限能力，默认关闭。
- 无 Socket 时 MediaSync 的同步功能必须完整可用。
- 一键升级只能管理唯一识别出的当前 MediaSync Appliance 容器。
- 一键升级不能成为通用 Docker 管理界面。
- 实际安装必须锁定官方镜像的精确版本和精确 digest。
- 更新前必须停止新任务领取并等待运行中任务结束。
- 数据库与运行时密钥必须在切换前形成一致性快照。
- 候选版本通过验证前不得执行 Provider 副作用。
- 候选版本失败时必须恢复旧镜像与更新前数据。
- Updater 助手不得常驻，结束后必须自动删除。
- 新容器权限不得高于旧容器。
- 高级 Compose 部署不在首个一键升级支持范围内。

## 后果

收益：

- 普通用户不需要常驻 Watchtower；
- 用户可以在 Web 后台完成完整镜像升级；
- 更新仍遵守不可变镜像、精确 digest 和可回滚原则；
- 默认用户不承担 Docker Socket 权限；
- 群晖、飞牛和普通 Docker 安装可以共享一套更新协议。

成本：

- 显式启用后，MediaSync 的攻击面扩大到宿主机 Docker；
- 需要维护容器识别、配置复制、任务排空、数据快照和回滚逻辑；
- 切换必须使用短生命周期助手容器；
- NAS 平台间的 Docker 行为差异进入测试矩阵；
- 升级期间 Web 服务会短暂中断；
- Compose、远程 Docker 和编排平台需要继续使用外部升级方式。

## 已考虑的备选方案

### 常驻 Watchtower

实现成熟，可以更新完整镜像，但要求普通用户额外部署一个高权限应用，不符合
默认单容器体验，因此不作为内置更新的前提。

### 容器内覆盖程序文件

不需要 Docker Socket，也能在重启时更新，但运行内容会偏离镜像 Tag，基础系统
依赖无法更新，下载中断还可能破坏程序目录，因此拒绝。

### 默认挂载 Docker Socket

安装后即可一键更新，但所有用户都会无条件授予宿主机 Docker 管理权限，违反
最小权限原则，因此拒绝。

### 只提供人工升级说明

安全且实现成本最低，但无法满足普通用户从 Web 后台完成升级的目标。保留为无
Socket 部署的降级路径，不作为唯一方案。

### 调用群晖或飞牛私有 API

可以利用 NAS 平台权限体系，但没有通用协议，会把核心更新能力绑定到特定平台，
因此首个实现不采用。

## 未来复审

出现以下情况时应通过新 ADR 复审本决定：

- Docker Engine 提供可限制为单容器更新的权限模型；
- 主流 NAS 提供稳定、统一的官方容器更新 API；
- 安全审计认为可选 Socket 的风险仍不可接受；
- 真实升级演练无法保证数据恢复和旧镜像回滚；
- 用户实际使用率不足以覆盖长期维护成本；
- 高级 Compose 成为绝大多数用户的默认部署方式。
