# ADR-0009：官方单容器安装默认配置 Docker Socket

- 状态：提议中
- 日期：2026-08-04
- 决策者：MediaSync 维护者
- 取代：ADR-0005
- 被取代：无
- 相关内容：[Docker Socket 一键镜像升级设计](../docker-socket-one-click-update.md)、PR #131

## 背景

ADR-0005 将 Docker Socket 定义为默认关闭的可选能力。该边界保证了最小权限，
但也使通过 Docker Hub、群晖或飞牛安装的普通用户默认看不到一键更新入口。用户
必须理解宿主机文件绑定，并在重建容器时手工增加 `/var/run/docker.sock`，这与
“安装后可在 Web 后台完成升级”的产品目标存在明显摩擦。

MediaSync 的一键更新实现已经限定官方镜像、精确 digest、唯一当前容器、任务排
空、候选验证和自动回滚，并通过真实 Docker daemon 与 NAS 重启演练。维护者因此
决定调整官方单容器安装的推荐安全默认值，让一键更新成为新安装的标准体验。

Docker 镜像元数据不能声明宿主机路径绑定。`Dockerfile` 中写入
`VOLUME /var/run/docker.sock` 只会创建匿名卷，不能连接宿主机 Docker daemon。
群晖和飞牛从 Docker Hub 镜像创建容器时，也不会根据镜像元数据自动生成宿主机
Socket 映射。因此“默认配置”必须由 Docker Run 命令、Compose 或平台安装模板
承担，不能由镜像在用户不知情时自行获得宿主机权限。

## 决策

MediaSync 官方单容器安装资料和受维护的安装模板默认配置以下读写绑定：

```text
/var/run/docker.sock:/var/run/docker.sock
```

这项默认值适用于面向普通用户的单容器 Appliance 新安装。安装界面或文档必须
在创建容器前明确说明：Docker Socket 使 MediaSync 拥有接近宿主机 Docker 管理
员的权限，用户可以删除该映射并继续使用全部同步功能和手动升级流程。

官方 OCI 镜像本身不得把 Docker Socket 声明为 `VOLUME`，也不得尝试发现或挂载
宿主机文件。无法由镜像自动表达绑定的平台必须在安装步骤中预先列出该映射；若
平台支持受维护的应用模板，则由模板带出默认值并要求用户确认。

高级多容器 Compose 不纳入首个默认启用范围。现有 updater 只支持唯一识别的单
容器 Appliance，不得为了让高级 Compose 显示更新按钮而把 Socket 广播给所有
API、Scheduler、Worker 或前端容器。

## 不变量

- Docker Socket 默认值只能由单容器安装命令或平台模板表达，不能伪装成镜像
  自动挂载能力。
- 安装前必须以清晰文字说明 Docker Socket 等同于 Docker 管理员权限。
- 用户删除 Socket 映射后，同步、订阅、转存、日志和手动升级必须完整可用。
- 一键更新仍只能操作唯一识别出的当前 MediaSync Appliance 容器。
- 一键更新不得成为通用 Docker 管理接口。
- 目标镜像必须来自允许列表，并锁定精确版本和 digest。
- 新容器只能复制白名单配置，权限不得高于被替换的容器。
- 更新前必须排空任务并创建一致性快照；候选失败必须自动回滚。
- Socket 不可访问、权限不足或当前容器无法唯一识别时必须安全降级，不得猜测。
- 管理页面不得直接暴露到公网；默认安装文档必须继续给出这一安全警告。
- 高级多容器 Compose 在独立设计完成前继续使用外部升级方式。

## 后果

收益：

- 按官方单容器步骤安装的普通用户默认可以在 Web 后台更新；
- 不再要求用户事后编辑容器才能发现已实现的一键更新能力；
- 默认体验与“单镜像、单端口、单目录”的 Appliance 产品方向保持一致；
- 用户仍可删除 Socket 映射，回到较小权限的手动升级模式。

成本与风险：

- 采用官方默认配置的 MediaSync 漏洞可能扩大为宿主机 Docker 管理风险；
- 群晖和飞牛原生的“从镜像创建容器”页面无法仅凭镜像自动带出该映射；
- 项目需要维护平台安装模板或用清晰步骤弥补平台限制；
- 安全提示不能消除 Socket 权限本身，只能让用户在安装前知情选择；
- 高级 Compose 与远程 Docker 仍不能使用内置一键更新。

## 非目标

- 不在镜像内运行 Docker daemon。
- 不把 `/var/run/docker.sock` 声明为镜像数据卷。
- 不绕过群晖、飞牛或 Docker 的宿主机权限确认界面。
- 不让 MediaSync 管理其他应用容器。
- 不在本决策中改变 updater 状态机、回滚协议或数据库模型。
- 不在本决策中宣布一键更新为稳定功能。

## 已考虑的备选方案

### 继续默认关闭

权限最小，但普通用户安装后无法直接使用项目已经实现并验证的一键更新能力，仍
需掌握容器重建和宿主机绑定，产品体验没有形成闭环，因此不再作为官方新安装的
推荐默认值。

### 在 Dockerfile 中声明 Socket VOLUME

表面上能让 NAS 界面看到一个容器路径，实际只会创建匿名卷，不会绑定宿主机
Docker Socket，既无法启用更新又会误导用户，因此拒绝。

### 给高级 Compose 的所有服务挂载 Socket

会把宿主机 Docker 权限扩散到多个进程，而且 updater 当前不支持 Compose 拓扑，
风险和行为都不正确，因此拒绝。

### 常驻 Watchtower

可以避免 MediaSync 自身持有 Socket，但要求普通用户增加另一个长期高权限应用，
也无法提供 MediaSync 内部任务排空和数据快照语义，因此不作为默认方案。

## 实现边界

设计通过后，独立实现 Issue 只允许调整：

- 官方单容器 `docker run` 示例；
- Docker Hub、飞牛和群晖安装说明；
- 项目维护的平台应用模板（若存在）；
- CI 对单容器默认安装契约的验证；
- 无 Socket 时的降级提示。

不得在该实现 Issue 中修改 updater 状态机、Provider、Task Engine、数据库或高级
Compose 拓扑。

## 未来复审

出现以下情况时应通过新 ADR 复审本决定：

- 主流 NAS 提供可限制到单个应用的官方更新 API；
- Docker 提供比完整 Engine Socket 更小权限的稳定本地更新接口；
- 安全审计认为默认 Socket 的风险超过一键更新带来的体验收益；
- 真实用户数据表明绝大多数人会主动删除默认映射；
- 项目提供签名 NAS 应用包，可由平台权限系统代替原始 Socket；
- 高级 Compose 成为普通用户的主要部署方式。
