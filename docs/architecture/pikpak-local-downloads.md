# PikPak 与可恢复本地下载

状态：已接受（[设计 PR #175](https://github.com/josephyin/MediaSync/pull/175)）。
关联现有 Task Engine v2、Provider 写入契约及
ADR-0001 单 Worker 决策。无数据库迁移，不增加 Worker 副本。

## 业务边界

本轮补齐 PikPak 登录、账号盘浏览、分享订阅与逐文件转存，以及将已转存的
PikPak 文件下载到运行 MediaSync 的服务器/NAS 挂载目录。下载独立于云盘转存状态，
不会删除云端文件。115、OneDrive、多用户和外部媒体库集成另行评审。

密码只用于本机调用固定官方登录域名，不保存或回显。仅加密保存可续期凭证和
客户端/设备标识。交互验证码停止自动处理，不尝试绕过。分享密码沿用加密存储。
分享子目录、空页和循环游标必须明确处理；不把失效子目录回退为整个分享。

## Provider 写入与核验

转存前记录写入意图；服务端确认后记录恢复核对标识。重启沿用标识核验唯一的
文件名、大小、hash 和完成状态，不重新提交已接受的转存。PikPak 先写默认接收目录
时，只移动唯一匹配文件至用户目标目录。超时或无法识别的写入结果进入
PROVIDER_WRITE_UNCERTAIN，保留证据并停止自动重放。

## 下载任务与持久化

- 使用现有 Task，type=download、payload_version=1；payload 固定 file_id 关联、
  提交时的绝对 root 和相对路径。URL、密码、Token 不进入 Task 或日志。
- API 只接受已转存的 PikPak 普通文件。同一文件、根目录和相对路径的非终态任务
  去重。手动重试创建新的后继 Task，历史 TaskRun 终态不可复用或改写。
- 管理员选择已存在可写目录；配置原子持久化。默认目录更改不影响已排队任务。
  API、Worker 和单容器使用相同持久化路径。下载路径禁止越界和符号链接。
- 临时文件与目标位于同一目录，使用排他文件锁。最终文件只经大小和可用 hash
  校验后原子发布，绝不覆盖已有目标。NAS 不支持原子发布则明确失败。
- 恢复信息绑定远端文件标识、大小及 hash；不得拼接另一个文件的旧分片。
  Range 响应必须验证起止位置和总长度。上游忽略 Range 时从头开始；不把 200
  全量响应追加到旧分片。签名链接每次执行时重新获取。
- 下载限速配置只影响网络读取；中断保留已落盘分片，取消不发布未完成文件。
  空间不足、权限错误、挂载不可用必须明确失败，不创建缺失的下载根目录。

## 有界执行与所有权

默认仍只有一个任务执行器。大文件下载按有界字节片段处理；每段释放任务租约，
以延迟可继续状态重新入队，让已到期扫描/转存可以执行。新增内部 deferred 结果
映射为持久化 pending；不增加持久化状态枚举，也不消耗失败重试预算。当前 Run
记录本段完成及 continuation 指标，不把整个下载标记为完成。

Worker 用现有 lock_token fencing 统一收尾；丢失所有权或取消后不得发布最终文件。
每次后继领取创建新 TaskRun。继续任务不改变历史运行结果。Legacy 调度器使用
相同分段下载逻辑和更新排空门禁；其取消/重试也保留终态记录。

## 运维信息

历史失败次数保留。仪表盘另外统计当前失败文件、凭证等待及尚未恢复的最新扫描/
下载问题；成功后仍有旧失败 Task 不应持续显示为当前故障。不得通过删除历史、
重写成功状态或盲目批量重试来消除警报。

## 验收与回滚

自动化覆盖登录脱敏、分享分页、转存一次性提交、恢复核验、下载 Range 206/200/
416、内容校验、取消/重启、去重、路径边界、文件锁、任务让行和历史不可变。
执行完整后端、迁移往返、前端测试/构建和单镜像 CI。

发布前用自有账号和专用目录复验真实转存、批量与嵌套目录、Token 刷新、实际下载
及 NAS 挂载。先确认镜像和真实运行版本，再声明上线。未通过的步骤逐项记录，
不能用 mock 代替。候选版验证后再决定正式版标签。

回滚保留整个 /data 及下载目录。旧版不消费 download 任务，回滚前必须安全排空或
取消下载；分片保留供兼容版本恢复。不得改写旧数据库来假装任务已完成。
