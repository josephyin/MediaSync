## 本轮实现

- 将既有未发布 PikPak 与本地下载源码保存在隔离分支，合并 v0.2.3 和已接受设计。
- 登录、刷新、分页、嵌套分享、一次性转存与目标核验；同名文件也核对内容指纹。
- 本地下载支持批量跨页选择、目录选择、Range 恢复、大小/GCID 校验及限速。
- 下载及内容校验分段释放唯一 Worker；延续不计入失败重试预算。
- 保留原子发布完成凭据，覆盖写入成功而数据库收尾前崩溃的恢复窗口。
- 终态下载手动重试创建后继 Task；保留 TaskRun 历史及云盘转存状态。
- 凭证异常可等待人工更新后继续；目录挂载身份改变时停止写入。
- 仪表盘分别显示当前待处理问题和历史失败次数，保留原始执行记录。
- 容器下载配置存放在持久化 /data/config；没有数据库迁移。

## 自动化与本地容器验证

本机完整后端 929 项、Ruff、前端 6 项测试及生产构建通过；全新数据库
upgrade/check/downgrade/upgrade 通过。单镜像构建与 Appliance 健康检查通过。
GitHub CI 单独在实现 PR 中核对，不能以本机通过代替远端结果。

本地隔离 Docker Desktop 容器使用独立临时 /data 和下载目录，不挂 Docker Socket，
只监听 127.0.0.1。使用 25 条明确标记的模拟文件和历史失败/成功记录检查：

- 仪表盘当前问题 0、历史失败 1，历史仍可见。
- 文件列表有本地下载入口；跨页全选弹窗确认包含 25 个文件。
- 下载目录选择器能浏览容器映射目录；未提交模拟账号的远端下载请求。
- API、Scheduler、Worker、Nginx、Launcher 复合健康检查通过。

以上是合成数据、HTTP mock 或本地挂载验证，不证明 PikPak 上游及真实 NAS 可用。
